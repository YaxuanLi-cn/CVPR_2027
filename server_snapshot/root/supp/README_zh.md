## 二、对论文结论有影响的结果（按影响大小排序）

以下数字都在补充材料里如实写出，并汇总在第 XI 节。措辞你可以改，但数字本身是实测。

### 1. 经典 SIFT 管线几乎追平 DreamNav，真实照片上更好（III、VIII）

"SIFT + 比值检验 + 本质矩阵(MAGSAC++) + 航高先验"，不含任何学习：

| | SR_d@1m | SR_EPE@1m |
|---|---|---|
| DreamNav Stage I | 73.1 | 59.9 |
| **SIFT 管线（全部 6,364 对）** | **78.2** | **73.6** |
| DreamNav Stage II | 83.3 | 78.7 |

- Stage II 只比 SIFT 高约 5 个点（+5.1 [3.9, 6.3] / +5.0 [3.8, 6.2]）；Stage I 低于 SIFT（−5.2 / −13.7）。
- RoMa（加四方向旋转搜索，200 对子集）81.5 / 79.0，与 Stage II（同一子集 85.5 / 81.5）差异不显著。
- **真实照片（Table 4 的 300 对，同样给 60 m 航高）**：SIFT 中位误差 0.53 m、SR_EPE 72.7%；RoMa（80 对）0.33 m、75.0%；DreamNav Stage II 0.84 m、57.7%。即真实数据上经典方法显著更好（SIFT 比 Stage II 高 15.0 个点 [8.2, 21.1]）。
- 我检查过这是否是因为数据集本身用 SIFT 筛过图像对：在 1,160 对**未筛选**图像对上，Stage II 60.9 / 55.4，SIFT 55.0 / 52.6，差距与筛选后一样（约 3–6 个点），所以不是筛选造成的。
- 其余学习型匹配器在其标准分辨率下明显弱于 SIFT：DeDoDe 65.5 / 54.1，LightGlue 51.3 / 35.3，LoFTR 49.9 / 35.5，ALIKED 41.1 / 20.5；MASt3R / DUSt3R 直接当位姿估计器基本失败（SR_EPE ≈ 0，其度量尺度差约 100 倍）。
- 所有几何方法（包括 DreamNav）的米制尺度都来自"航高约 220 m"这个数据集规律。

**后果**：摘要里"优于广泛使用的相对位姿回归器"的说法站不住——Table 2 的 8 个基线不是位姿估计器；与真正的几何估计器相比，优势是 5 个点（PairUAV）或为负（真实照片）。

### 2. "几何想象"（地面单应）本身贡献很小（IV.2、III.4）

精修阶段的增益（3,000 对：SR_d +9.2，SR_EPE +17.8）来自哪里：

| 第二次匹配的方式 | SR_d | SR_EPE |
|---|---|---|
| 粗阶段 | 73.5 | 60.5 |
| 只加一层融合、不重新匹配 | 72.4 | 58.0 |
| **只按粗位姿的旋转对齐 + 同样的原分辨率分块（等计算量，无平面）** | **82.1** | **76.0** |
| 平面单应，但只匹配 1 块 | 77.5 | 65.8 |
| 平面单应，512×288 分辨率 | 72.3 | 57.1 |
| 平面单应 + 分块（论文方法） | 82.7 | 78.3 |
| **粗阶段融合 + SIFT 候选（完全没有想象）** | **81.8** | **76.6** |
| 精修阶段 + SIFT 候选 | 84.1 | 80.6 |

- 旋转对齐就拿到了约九成增益；平面单应只多 2.2 个 SR_EPE 点 [1.1, 3.5]，SR_d 上无显著差异。它只在大倾角（35–45°，+5.1）和大高度差（≥25 m，+3.5）时有用。
- 用真值位姿做单应也不比用粗位姿好（3,404 vs 3,408 个内点）——对齐精度不是瓶颈。
- 假设验证分数（verification scores）去掉后结果不变。
- 512 分辨率下的"想象"比不精修还差——这一条对你有利：可用来论证扩散模型式的想象在这个精度区间不可行（X 节用了这个论据）。
- 完全不用位姿引导（只转 90° 的倍数）时分块匹配直接失败（内点中位数 12）——粗位姿的旋转是必要的。
- **真正优于经典几何的部件是"可靠性加权融合"**：同样的 SIFT 匹配，经融合后比 SIFT 管线高 3.4 / 2.8 个点；全系统 + SIFT 候选达到 84.1 / 80.6，是目前 PairUAV 上最好的结果。

**后果**：标题和摘要把贡献归于"几何想象 / 地面单应"，实验支持的表述应是"位姿引导的原分辨率重匹配 + 学习融合"。

### 3. SR 的定义与 Table 3 的两处问题（II、IV.1）

- 论文写 SR 是"三维距离 ≤1 m"，实际 Table 2–4 用的是"预测距离与真实距离之差 ≤1 m"。按三维端点误差：Stage II 相机系 78.7%、ENU 61.9%（不是 83.3%）；Stage I 59.9% / 44.3%。补充材料两种都报（按你之前的决定，距离差 SR 仍作为主列）。
- Table 3 第 1 行"Frozen SuperGlue"实际是 MASt3R 统计特征回归，没有用任何匹配。真正的"单次 SuperGlue"是 22.8%（53.8% 的图像对求不出位姿）。
- Table 3 第 3 行"+ absolute heading"的 2.25 m / 35.1% **在任何实验记录里都复现不出来**，重算是 1.14 m / 65.1%（航向不可能改变距离误差，审稿人的质疑是对的）。因此"zoom 重匹配 +38 个点"应为 +8.0，正文 5.2 节对应的两句话需要撤回。35.1% 恰好等于该配置在 ENU 下的端点成功率，可能是当时填表时混用了两种定义——请你核实原始记录。

### 4. Table 5 的 "Ours (Stage II)" 含有论文没写的近距离求解器（VII）

- 这一行在估计剩余距离 < 5 m 时改用地面平面线性求解平移（`online/plane_servo.py`）。把三者拆开（τ = 1 m，4 次执行噪声抽样的均值 ± 标准差）：粗阶段 50.3 ± 5.9%，粗 + 精修 49.8 ± 4.5%，再加近距离求解器 80.3 ± 4.6%（论文 Table 5 那一次抽样分别是 56.9 / 55.6 / 81.9，偏乐观）。这个求解器在该行 68.8% 的决策步中接管了平移（99.4% 的回合至少用到一次）。即 **Table 5 的提升来自这个求解器，而不是精修阶段**（精修 − 粗：−0.5 [−5.8, +5.2]；求解器的贡献：+30.5 [25.6, 35.2]）。
- 不设停止规则时，粗阶段和精修阶段在第 2 步之后成功率反而下降（粗阶段 39.5% → 22.0%，精修 34.2% → 17.7%）：离目标几米内估计不准，会把相机又带远。
- 摘要里"迭代精修 2.2 次…闭环在估计器内部完成"与实际不符：2.2 是物理步数；在固定图像对上内部迭代 3 轮只有 +1.3 [−0.3, +2.8] 到 +1.9 [+0.4, +3.5] 个点（取决于迭代协议）。
- 经典 IBVS（增益 0.5、20 步）最终 91.2% 到达 1 m 内，高于 Table 5 的任何一行；但 55.6% 的轨迹中途会偏离 50 m 以上，且需要约 10 步。
- 单步 38.8% 与 Table 2 的 83.3% 之间的差距已逐项分解：定义（→78.7）→ 起止对未筛选、40% 超出训练范围（→60.6）→ 仿真渲染域差（→48.1）→ 执行噪声（→39.5 的期望，单次抽样落在 [35.0, 44.4]）。

### 5. 绝对航向先验不泛化（V）

- 融合后航向误差：均值 5.3°、中位数 1.3°，1.9% 超过 45°；相当于一个误差 2–5° 的指南针。
- 测试建筑与最近训练建筑的中位距离只有 103 m。距离 <100 m 时 ENU 成功率 74.4%，>5 km 时 13.3%；相机系成功率不受影响。
- **把 6 个站点的全部训练建筑去掉后重训航向网络**：这些站点上的 ENU 端点成功率从 67.5% 降到 27.4%（−40.1 [−45.4, −35.3]），相机系仍是 78.4%。
- 图像扰动实验：去掉颜色（中位误差 36°）、色相旋转、反色（57% 的预测翻转 180°）、强压缩都会破坏它；南半球 3 栋建筑误差约 140°；亮度/对比度/打乱 64 px 图块则几乎无影响。这与"读阴影方向"的解释一致（未能直接验证）。
- 真实照片上中位误差 35°，ENU 成功率 7.3%（相机系 57.7%）。
- 审稿人问"基线是不是因为 ENU 才失败"：6 个基线改用相机系目标重训后**没有任何变化**（它们根本感知不到位移）；π0.5 与 π0-FAST 因显存未能重训。

**后果**："unseen scenes" 应改为 "unseen buildings"；Table 2/3 的 Δx、Δy 列依赖一个只在 PairUAV 站点上成立的先验；建议以相机系结果为主。

### 6. 真实照片实验的两个前提（VIII）

- DreamNav 的输出乘了 60/220.2（飞机上报的航高），论文没写；不给航高时中位误差 16.4 m。
- 只在训练的基线/航高比范围内成立；范围外的 300 对端点成功率 1.7%（预测零运动的误差是 21.7 m，DreamNav 是 18.0 m）。

### 7. 其他

- 场景并不平坦：起伏中位数为航高的 8.6%，64% 的匹配点高出地面 3 m 以上。精修增益随起伏下降但始终为正（<5%：+29.3；≥20%：+13.6）。贴近立面飞行（论文动机里的"阳台"）没有被任何实验覆盖，补充材料里明确写了不做此声明。
- 未筛选图像对：Stage II 60.9 / 55.4；两视野重叠 <2% 的图像对（占 23%）任何方法都解不了，但 DreamNav 仍会输出一个估计。
- 运行时间：2.80 s / 对（0.36 Hz，RTX 5090），其中航向网络 1.09 s。

## 四、实验的局限（已写进 PDF 的相应位置）

- 对照实验（IV.2、III.4）在 3,000 测试对上做，融合用 3,000 训练对重新拟合（论文用 12,000）；用 12,000 时完整精修为 84.0 / 79.4，差 1.3 个点以内。
- RoMa 与 MASt3R 描述子匹配因 GPU 共享只跑了 200 对（真实照片 80 / 100 对）。
- 学习型匹配器用的是各自公开配置的分辨率（长边 1024–1152），没有调到更高分辨率；SIFT 用的是半分辨率（1843 px）。
- 航向跨站点重训只重训了 raw-view 网络（另一个网络单次训练需近 3 小时）；一个划分、一个种子；等规模对照只训了 3/10 个 epoch。
- 闭环只重采样了执行噪声（4 个种子，160 个回合、8 个站点不变），估计器本身是确定性的。
- π0.5、π0-FAST 没有做相机系重训。
- 真实数据仍只有一个场景（Mézières）。
